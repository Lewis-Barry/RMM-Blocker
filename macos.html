Block remote tools on macOS 27 by code signature. Exclude the ones you trust.

PreviewNew. Requires macOS 27 and a supervised Mac (Automated Device Enrollment). There is no audit mode: a deployed rule blocks immediately. Test on a non-production device.

How to use

  1. Find each remote tool your team uses, then tick Exclude.
  2. Download the Intune JSON and create the policy through Graph, or download the Apple declaration for another MDM. Deployment guide.
  3. Pilot on one test Mac before a wider rollout. The Defender IOCs on the RMM tab also block these tools' domains on macOS.

      Is this perfect?

      No. Rules match the vendor's code signature, so renaming or moving an app does not get past them, but a tool that ships unsigned or ad-hoc signed has no Team ID to match. Open-source tools built from source are the usual gap.

      Where a vendor's Team ID also signs unrelated software, such as Google, only the remote desktop binaries are denied by Signing ID. A new helper binary with a new Signing ID is not covered until the list is updated.

      The list is far shorter than the Windows one: every entry was verified against a real installer. Pair it with the Defender IOCs, which also work on macOS, and test on pilot devices first.
