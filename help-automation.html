Automate

One PowerShell script keeps the WDAC policy, the macOS deny list and the Defender indicators in your tenant in line with this site. Run it on a schedule and new tools are blocked without downloading anything.

The policies are enforced. Run the script with -WhatIf first: it shows what would change and changes nothing.

1. Requirements

WDAC and macOSMicrosoft Intune Plan 1, for example through Microsoft 365 Business Premium, E3 or E5.
Windows devicesWindows 11 24H2 or newer, Pro, Enterprise or Education, enrolled in Intune. The rules use wildcards older Windows does not support.
MacsmacOS 27 or newer, supervised through Automated Device Enrollment.
Defender indicatorsMicrosoft Defender for Endpoint Plan 1 or 2, or Defender for Business. In the Defender portal turn on Settings → Endpoints → Advanced features → Custom network indicators, and set network protection to block mode.
A place to run itA GitHub repository, an Azure DevOps project or an Azure Automation account. Your own computer is enough to try it.
PowerShell7.4 or later.
Admin for the setupGlobal Administrator, or Cloud Application Administrator plus Privileged Role Administrator. Needed once, to create the app.

You only need the licences for what you sync. Without Defender for Endpoint, run with -Target Wdac,Macos; otherwise WDAC and macOS are synced and only the indicators fail.

2. Downloads

  • Sync-RMMGuard.ps1The sync script. Downloads the lists, checks them and updates the policies and indicators.
  • Setup-RMMGuardApp.ps1One-time setup. Creates the app the sync script signs in with, and removes it again.
  • github-workflow.ymlGitHub Actions template (option 1).
  • azure-pipelines.ymlAzure DevOps template (option 2).

3. App registration

The sync script signs in as an app with two permissions: Microsoft Graph DeviceManagementConfiguration.ReadWrite.All and WindowsDefenderATP Ti.ReadWrite. Setup-RMMGuardApp.ps1 creates it and grants admin consent. Pick the sign-in that matches where the script will run.

Certificate

For your own computer or a pipeline with a certificate. Works in tenants that block client secrets. The private key is saved as ~/RMMGuardSync-<TenantId>.pfx, protected with a password you choose.

./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com

OIDC

For GitHub Actions: no secret and no certificate. The subject names your repository and branch.

./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -CredentialType None -FederatedSubject 'repo:contoso/rmm-guard:ref:refs/heads/main'

For Azure DevOps, create the app with -CredentialType None and add the federated credential from the service connection (option 2).

Managed identity

For an Azure Automation account. Creates no app; it gives the account's managed identity the two permissions.

./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -ManagedIdentityObjectId <object id>

Remove

Deletes the app, its permissions and its default .pfx (pass -CertificatePath if you saved it elsewhere). With -ManagedIdentityObjectId it takes the permissions away from the managed identity.

./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -Remove

The setup script prints the ClientId you need in the next steps.

Imported the indicator CSVs by hand before? The app only sees the indicators it created itself. Delete the indicators you imported (their titles start with LOLRMM), otherwise you end up with two sets. An indicator of your own for the same domain or IP, such as an Allow for a tool you use, is changed to Block: exclude that tool instead.

4. Parameters

-TargetWhat to sync. Default All: WDAC, macOS and the Defender indicators. To sync less, name them: -Target Macos or -Target Wdac,Ioc. With -Interactive, All skips the indicators, which need the app.
-WdacPolicyNameName of the WDAC policy in Intune. Default RMM Guard - WDAC. Created when it does not exist.
-MacosPolicyNameName of the macOS policy. Default Block RMM tools (macOS), the name of this site's export. Must differ from the WDAC name: they are two separate policies. Defender indicators have no policy name.
-ExcludeTools to leave out, as the RMM page names them: -Exclude 'AnyDesk','TeamViewer'.
-AssignmentAllDevices, AllUsers or a group object ID. Added to the policy's assignments; existing ones are kept. Without it, a new policy is created unassigned. Indicators always apply to the whole tenant.
-MinimumReleaseAgeDaysNew blocks wait until the release is this many days old, for example 7. An update that only removes blocks, such as a new exclusion, applies at once. A new -Assignment waits with the update, so devices never get an outdated list.
-WhatIfShow what would change without changing it.
Sign-inOne of:
  • -Interactive: your own admin account. WDAC and macOS only; Defender needs the app.
  • -CertificatePath: the .pfx, with its password in $env:RMMGUARD_CERT_PASSWORD or -CertificatePassword. On Windows also -CertificateThumbprint for a certificate in the certificate store.
  • -FederatedToken: an OIDC token from GitHub Actions or Azure DevOps.
  • -Identity: the managed identity of an Azure Automation account.
  • -ClientSecret or $env:RMMGUARD_CLIENT_SECRET: a client secret.
Every sign-in except -Interactive and -Identity also needs -TenantId and -ClientId.

Examples

Everything, assigned to all devices:

./Sync-RMMGuard.ps1 -Assignment AllDevices -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ~/RMMGuardSync-contoso.onmicrosoft.com.pfx

Only macOS, as a preview with your own account:

./Sync-RMMGuard.ps1 -Target Macos -Interactive -WhatIf

Only WDAC, without AnyDesk and TeamViewer:

./Sync-RMMGuard.ps1 -Target Wdac -Exclude 'AnyDesk','TeamViewer' -Interactive

Only the Defender indicators:

./Sync-RMMGuard.ps1 -Target Ioc -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ~/RMMGuardSync-contoso.onmicrosoft.com.pfx

Already deployed the policies by hand from this site? Pass the names you gave them; the script updates them in place. The Copy custom retrieval links window on the RMM page shows the command with your current exclusions.

5. Deployment

Pick one place to run the script every week.

Option 1: GitHub Actions

  1. Create a private repository and add Sync-RMMGuard.ps1 to its root.
  2. Create the app with the OIDC command, with your repository in the subject.
  3. Add the workflow below as .github/workflows/rmm-guard-sync.yml and fill in the values under env.
  4. Actions → RMM Guard sync → Run workflow, then check the policies in Intune. After that it runs every Monday.
TENANT_IDThe TenantId the setup script printed.
CLIENT_IDThe ClientId the setup script printed.
ASSIGNMENTAllDevices, AllUsers or the object ID of a group. Leave it empty to create the policies unassigned.
EXCLUDEThe tools you want to keep using, separated by commas: AnyDesk,TeamViewer. Leave it empty to block every tool.
 
# RMM Guard sync. Guide: https://rmmguard.com/help-automation.html#github
name: RMM Guard sync
on:
  schedule:
    - cron: '0 6 * * 1'   # Mondays 06:00 UTC
  workflow_dispatch:
permissions:
  contents: read
  id-token: write
env:
  TENANT_ID: ''
  CLIENT_ID: ''
  ASSIGNMENT: ''          # AllDevices, AllUsers or a group object ID; empty creates the policies unassigned
  EXCLUDE: ''             # tools to leave out, e.g. AnyDesk,TeamViewer
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Sync RMM Guard
        shell: pwsh
        run: |
          $token = (Invoke-RestMethod -Uri "$env:ACTIONS_ID_TOKEN_REQUEST_URL&audience=api://AzureADTokenExchange" `
            -Headers @{ Authorization = "Bearer $env:ACTIONS_ID_TOKEN_REQUEST_TOKEN" }).value
          $sync = @{
            Exclude        = @($env:EXCLUDE -split ',' | ForEach-Object Trim | Where-Object { $_ })
            TenantId       = $env:TENANT_ID
            ClientId       = $env:CLIENT_ID
            FederatedToken = $token
          }
          if ($env:ASSIGNMENT) { $sync.Assignment = $env:ASSIGNMENT }
          ./Sync-RMMGuard.ps1 @sync

Option 2: Azure DevOps

  1. Add Sync-RMMGuard.ps1 and azure-pipelines.yml to the root of an Azure Repos repository.
  2. Create the app with ./Setup-RMMGuardApp.ps1 -TenantId <tenant> -CredentialType None.
  3. Project settings → Service connections → New → Azure Resource Manager → Workload identity federation (manual). Name it rmm-guard and enter the tenant, the ClientId and a subscription the app has Reader on (the task requires one). Copy the Issuer and Subject identifier.
  4. In Entra, open the app → Certificates & secrets → Federated credentials → Add → Other issuer, paste both values, then finish the service connection.
  5. Pipelines → Library → + Variable group. Name it rmm-guard and add the two variables below.
  6. Create the pipeline from the YAML file and run it once by hand.
VariableValue
ASSIGNMENTAllDevices, AllUsers or the object ID of a group. Leave it empty to create the policies unassigned.
EXCLUDEThe tools you want to keep using, separated by commas: AnyDesk,TeamViewer. Leave it empty to block every tool.

Option 3: Azure Automation Runbooks

  1. In the Automation account: Identity → System assigned → On. Copy the Object (principal) ID and run the managed identity setup command with it.
  2. Runtime Environments: PowerShell 7.4 with the module Microsoft.Graph.Authentication.
  3. Runbooks → Create: type PowerShell, runtime 7.4. Paste Sync-RMMGuard.ps1 and Publish.
  4. In the runbook: Link to schedule → a weekly schedule → Parameters and run settings, and fill in:
ParameterValue
IDENTITYTrue. The runbook signs in with the managed identity.
ASSIGNMENTAllDevices, AllUsers or the object ID of a group. Leave it empty to create the policies unassigned.
EXCLUDEThe tools you want to keep using, separated by commas: AnyDesk,TeamViewer. Leave it empty to block every tool.

Leave the other parameters empty.

6. Safety checks

Before it changes anything, the script stops when:

  • a WDAC rule would block a Windows, PowerShell, .NET, Office, Edge, Teams, OneDrive, Defender or Intune file or folder, or any .dll other than the ones RMM Guard blocks today;
  • an indicator would block a Microsoft or Apple domain, such as sign-in, Intune or Windows Update;
  • a macOS rule would block Microsoft apps, such as Company Portal or Defender;
  • a policy with the chosen name exists but was not created by RMM Guard.

7. Troubleshooting

ProblemWhat to do
The run stops with HTTP 400: unknown tool in exclude.A tool in your exclusions was renamed or removed on this site. Copy the names again from the RMM page.
The run stops because a rule would block Windows, Intune or a Microsoft domain.Nothing was changed for that part (WDAC, macOS or the indicators). Report it ↗.
The run refuses to overwrite a policy.A policy with that name exists, but RMM Guard did not create it. Choose another name with -WdacPolicyName or -MacosPolicyName.
The run says the RMM Guard policy already exists under another name.You deployed it by hand earlier. Pass that name with -WdacPolicyName.
The run stops because the WDAC rule options were changed by hand.Someone changed the policy, for example to Audit Mode. Change it back in Intune, or sync to another policy name.
The run says the RMM Guard policy is also deployed under another name.Two Intune policies carry the same WDAC policy, and Windows runs it only once per device. Delete the one the script does not sync.
The run stops because the indicator list is empty.The published list is broken. Nothing was deleted. Report it, as above.
Only the indicators fail, with Defender sign-in failed.The tenant has no Defender for Endpoint, or the app lacks Ti.ReadWrite. Run with -Target Wdac,Macos, or rerun the setup script.
The run skips an update because the release is too new.Expected with -MinimumReleaseAgeDays. A later run applies it.
Sign-in fails with AADSTS700213 or AADSTS70021.The federated credential does not match. Check the repository and branch in its subject; scheduled runs use main.
The setup fails with CredentialTypeNotAllowedAsPerAppPolicy.Your tenant blocks client secrets. Use a certificate or OIDC.
