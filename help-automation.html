WDAC Defender IOCs macOS Automation

Automate

One PowerShell script keeps the WDAC policy, the macOS deny list and the Defender indicators in your tenant up to date with this site. Run it on a schedule and new tools are blocked without anyone downloading a file.

The policies are enforced. Every run can change what your devices block. Keep a pilot group, and let production follow a week later.

1. How it works

  1. The script downloads the retrieval links with your exclusions: /api/wdac.xml, /api/macos.json and /api/iocs.csv.
  2. It checks every file against fixed safety checks (step 7) before anything is sent to your tenant.
  3. It finds your policy by name. Missing: it creates it and assigns it. Present: it compares and only writes when something changed.
  4. Defender indicators are compared one by one: new ones are imported, changed ones updated, removed ones deleted.

Every run ends with one line per target: created, updated, unchanged or skipped. Needs PowerShell 7.4 or later.

2. Downloads

  • Sync-RMMGuard.ps1The sync script. Runs on every schedule: downloads, checks and writes the policies and indicators. Put it next to your pipeline file, or paste it into a runbook.
  • Setup-RMMGuardApp.ps1One-time setup. Creates the app registration with its two permissions and a credential, or grants the permissions to a managed identity. With -Remove it takes everything away again.
  • github-workflow.ymlGitHub Actions template with a pilot and a production job (option 1).
  • azure-pipelines.ymlAzure DevOps template with a pilot and a production stage (option 2).

Download the sync script again now and then: fixes to its checks only reach you that way.

3. App registration

The script signs in as an app with two permissions: Microsoft Graph DeviceManagementConfiguration.ReadWrite.All (WDAC and macOS policies) and WindowsDefenderATP Ti.ReadWrite (Defender indicators). Sign in to the setup script as Global Administrator, or as Cloud Application Administrator plus Privileged Role Administrator.

# Certificate (default; works in tenants that block client secrets).
# The private key is saved as ~/RMMGuardSync-<TenantId>.pfx, protected with a password you choose.
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com

# OIDC for GitHub Actions: no secret and no certificate
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -CredentialType None -FederatedSubject 'repo:contoso/rmm-guard:ref:refs/heads/main'

# Managed identity of an Azure Automation account: grants the permissions, creates no app
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -ManagedIdentityObjectId <object id>

# Remove the app, its permissions and its .pfx again
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -Remove

The script prints the ClientId you need later. A client secret is possible with -CredentialType Secret, but many tenants block secrets and they expire; prefer OIDC or a certificate.

Indicators you imported by hand. Ti.ReadWrite only lets the app see the indicators it created itself. If you imported the CSVs from this site by hand before, delete those LOLRMM - … indicators in Defender first; otherwise both sets stay. An indicator of your own for the same domain or IP, for example an Allow for a tool you use, is turned into a Block by the import: exclude that tool with -Exclude instead.

4. Try it locally

Start with a dry run under your own Intune admin account. -WhatIf shows what would change without changing anything:

./Sync-RMMGuard.ps1 -Target Wdac,Macos -WdacPolicyName 'RMM Guard - WDAC' -Interactive -WhatIf

Defender indicators need the app, because the Defender API does not accept a personal sign-in:

$env:RMMGUARD_CERT_PASSWORD = Read-Host 'Certificate password' -MaskInput
./Sync-RMMGuard.ps1 -Target Ioc -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ~/RMMGuardSync-contoso.onmicrosoft.com.pfx -WhatIf

Already deployed the policies by hand from this site? Pass their names: the macOS export is called Block RMM tools (macOS), and for WDAC use the name you gave it. The script recognises them and updates them in place. If it finds the RMM Guard WDAC policy under another name, it stops and tells you which name to pass.

5. Parameters

-TargetWhat to sync: Wdac, Macos, Ioc, or any combination such as Wdac,Macos. Required.
-WdacPolicyNameName of the WDAC (App Control for Business) policy in Intune. Required with Wdac. Created when it does not exist.
-MacosPolicyNameName of the macOS settings catalog policy. Default Block RMM tools (macOS), the name of this site's macOS export.
-ExcludeTools to leave out, exactly as the RMM page names them, e.g. 'AnyDesk','TeamViewer'. Applies to all three targets.
-AssignmentAllDevices, AllUsers or the object ID of an Entra group. Added to the policy's assignments; existing assignments are never removed. Leave it out to create the policy unassigned. Defender indicators always apply to the whole tenant.
-ExcludeGroupIdObject ID of a group to exclude from the assignment, normally your pilot group on the production policy. Not with -Assignment AllUsers for WDAC: Intune does not reliably exclude device groups from a user assignment.
-RingPolicyNameName of the other ring's WDAC policy (pilot and production share one PolicyID). The script then does not treat it as a duplicate, and refuses to assign when a device could get both.
-MinimumReleaseAgeDays0 to 365, default 0. A change that adds rules or indicators waits until the published version is this many days old. Changes that only remove rules always apply at once.
-ForceApply a change that adds or removes more than 25 percent of the deployed rules or indicators, or that resets rule options someone changed by hand. Check the change with -WhatIf first.
-WhatIfShow what would change, change nothing.
Sign-in, pick one-Interactive (your own account; WDAC and macOS only), -Identity (managed identity in Azure Automation), -FederatedToken (OIDC from a pipeline), -CertificatePath with the password in $env:RMMGUARD_CERT_PASSWORD or -CertificatePassword, -CertificateThumbprint (Windows certificate store), or -ClientSecret / $env:RMMGUARD_CLIENT_SECRET. All app sign-ins also need -TenantId and -ClientId.

Examples:

# macOS only, assigned to one group
./Sync-RMMGuard.ps1 -Target Macos -Assignment <group object id> -Interactive

# WDAC only, without AnyDesk and TeamViewer, for all devices
./Sync-RMMGuard.ps1 -Target Wdac -WdacPolicyName 'RMM Guard - WDAC' -Exclude 'AnyDesk','TeamViewer' -Assignment AllDevices -Interactive

# Defender indicators only
./Sync-RMMGuard.ps1 -Target Ioc -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ./RMMGuardSync.pfx

# Everything, production ring after a week
./Sync-RMMGuard.ps1 -Target Wdac,Macos,Ioc -WdacPolicyName 'RMM Guard - WDAC' -RingPolicyName 'RMM Guard - WDAC (pilot)' `
    -Assignment AllDevices -ExcludeGroupId <pilot group id> -MinimumReleaseAgeDays 7 `
    -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ./RMMGuardSync.pfx

The Copy custom retrieval links window on the RMM page shows the command with your current exclusions.

6. Deployment

Pick one place to run the script on a schedule. All three run a pilot ring first and production later:

  • Option 1: GitHub Actions. A private repository and OIDC: no secret to store or rotate.
  • Option 2: Azure DevOps. A pipeline with a workload identity federation service connection.
  • Option 3: Azure Automation Runbooks. A managed identity in your own Azure subscription.

Option 1: GitHub Actions

  1. Create a private repository and add Sync-RMMGuard.ps1 to its root.
  2. Create the app with a federated credential for that repository. The subject must name the branch the workflow runs on; scheduled runs use the default branch: 
    ./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -CredentialType None -FederatedSubject 'repo:<owner>/<repo>:ref:refs/heads/main'
  3. Create .github/workflows/rmm-guard-sync.yml with the workflow below and fill in the four values under env. With OIDC none of them is a secret.
  4. Actions → RMM Guard sync → Run workflow. Check both jobs, then the policies in Intune. After that it runs every Monday at 06:00 UTC.
TENANT_IDThe TenantId the setup script printed, or Entra admin center → Overview → Tenant ID.
CLIENT_IDThe ClientId the setup script printed.
PILOT_GROUP_IDEntra admin center → Groups → your pilot device group → Object ID. Production excludes this group.
EXCLUDETools to leave out, comma-separated, e.g. AnyDesk,TeamViewer. Empty to block everything.
 
# RMM Guard sync for GitHub Actions.
# Copy to .github/workflows/rmm-guard-sync.yml in a private repository, with Sync-RMMGuard.ps1 in the repository root,
# and fill in the four values under env. With OIDC none of them is a secret.
# Guide: https://rmmguard.com/help-automation.html#github
name: RMM Guard sync
on:
  schedule:
    - cron: '0 6 * * 1'   # Mondays 06:00 UTC
  workflow_dispatch:
    inputs:
      force:
        description: Apply a change larger than 25 percent (after checking it with a normal run)
        type: boolean
        default: false
permissions:
  contents: read
  id-token: write          # lets the job request an OIDC token for the app's federated credential
env:
  TENANT_ID: ''            # Directory (tenant) ID, e.g. 00000000-0000-0000-0000-000000000000
  CLIENT_ID: ''            # ClientId printed by Setup-RMMGuardApp.ps1
  PILOT_GROUP_ID: ''       # object ID of the Entra device group that gets new versions first
  EXCLUDE: ''              # tool names to leave out, comma-separated, exactly as on rmmguard.com, e.g. AnyDesk,TeamViewer
  FORCE: ${{ inputs.force }}
jobs:
  pilot:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Sync the pilot policies
        shell: pwsh
        run: |
          $token = (Invoke-RestMethod -Uri "$env:ACTIONS_ID_TOKEN_REQUEST_URL&audience=api://AzureADTokenExchange" `
            -Headers @{ Authorization = "Bearer $env:ACTIONS_ID_TOKEN_REQUEST_TOKEN" }).value
          ./Sync-RMMGuard.ps1 -Target Wdac,Macos `
            -WdacPolicyName 'RMM Guard - WDAC (pilot)' -MacosPolicyName 'RMM Guard - macOS (pilot)' `
            -RingPolicyName 'RMM Guard - WDAC' `
            -Exclude ($env:EXCLUDE -split ',' | ForEach-Object Trim | Where-Object { $_ }) `
            -Assignment $env:PILOT_GROUP_ID -Force:($env:FORCE -eq 'true') `
            -TenantId $env:TENANT_ID -ClientId $env:CLIENT_ID -FederatedToken $token
  production:
    needs: pilot           # a pilot run stopped by a safety rule also stops production
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Sync the production policies and Defender indicators
        shell: pwsh
        run: |
          $token = (Invoke-RestMethod -Uri "$env:ACTIONS_ID_TOKEN_REQUEST_URL&audience=api://AzureADTokenExchange" `
            -Headers @{ Authorization = "Bearer $env:ACTIONS_ID_TOKEN_REQUEST_TOKEN" }).value
          ./Sync-RMMGuard.ps1 -Target Wdac,Macos,Ioc -MinimumReleaseAgeDays 7 `
            -WdacPolicyName 'RMM Guard - WDAC' -MacosPolicyName 'RMM Guard - macOS' `
            -RingPolicyName 'RMM Guard - WDAC (pilot)' `
            -Exclude ($env:EXCLUDE -split ',' | ForEach-Object Trim | Where-Object { $_ }) `
            -Assignment AllDevices -ExcludeGroupId $env:PILOT_GROUP_ID -Force:($env:FORCE -eq 'true') `
            -TenantId $env:TENANT_ID -ClientId $env:CLIENT_ID -FederatedToken $token
# Certificate instead of OIDC: store the .pfx as base64 in secret RMMGUARD_CERT_BASE64 and its password in
# RMMGUARD_CERT_PASSWORD, then in both jobs replace the two token lines and -FederatedToken $token with:
#   env:
#     RMMGUARD_CERT_BASE64: ${{ secrets.RMMGUARD_CERT_BASE64 }}
#     RMMGUARD_CERT_PASSWORD: ${{ secrets.RMMGUARD_CERT_PASSWORD }}
#   run: |
#     [IO.File]::WriteAllBytes("$env:RUNNER_TEMP/rmmguard.pfx", [Convert]::FromBase64String($env:RMMGUARD_CERT_BASE64))
#     ./Sync-RMMGuard.ps1 ... -CertificatePath "$env:RUNNER_TEMP/rmmguard.pfx"
# Client secret (only if your tenant allows secrets): store it in secret RMMGUARD_CLIENT_SECRET, add
#   env:
#     RMMGUARD_CLIENT_SECRET: ${{ secrets.RMMGUARD_CLIENT_SECRET }}
# and drop the token lines and -FederatedToken $token; the script reads the variable itself.

Rename the policies in the workflow if you like; keep each -RingPolicyName pointing at the other job's WDAC policy. When a run stops on the 25 percent check, run the workflow by hand with force ticked after checking the numbers. Certificate instead of OIDC: the end of the workflow shows the two secrets and the lines to change.

Option 2: Azure DevOps

  1. Add Sync-RMMGuard.ps1 and azure-pipelines.yml to the root of an Azure Repos repository.
  2. Run Setup-RMMGuardApp.ps1 -CredentialType None and note the ClientId.
  3. Project settings → Service connections → New → Azure Resource Manager → Workload identity federation (manual). Name it rmm-guard, enter the tenant, the ClientId and any subscription the app can read (the task requires one; give the app the Reader role on it). Copy the Issuer and Subject identifier it shows.
  4. In Entra, open the app → Certificates & secrets → Federated credentials → Add → Other issuer, and paste both values. Then finish the service connection.
  5. Pipelines → Library → variable group rmm-guard with RMMGUARD_PILOT_GROUP_ID (object ID of the pilot device group) and EXCLUDE (comma-separated tool names, may be empty).
  6. Create the pipeline from the YAML file and run it once by hand. The force parameter on a manual run applies a change above 25 percent.

Option 3: Azure Automation Runbooks

  1. In your Automation account, Identity → System assigned → On. Copy the Object (principal) ID.
  2. Grant the permissions to it: ./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -ManagedIdentityObjectId <object id>.
  3. Runtime Environments: use PowerShell 7.4 and add the module Microsoft.Graph.Authentication from the gallery.
  4. Runbooks → Create, type PowerShell, runtime 7.4. Paste the contents of Sync-RMMGuard.ps1 and Publish.
  5. Add two weekly Schedules to the runbook, the pilot one first in the week, each with these parameters:
PilotTARGET ["Wdac","Macos"], WDACPOLICYNAME RMM Guard - WDAC (pilot), MACOSPOLICYNAME RMM Guard - macOS (pilot), RINGPOLICYNAME ["RMM Guard - WDAC"], ASSIGNMENT your pilot group ID, EXCLUDE your tool names, IDENTITY true.
ProductionTARGET ["Wdac","Macos","Ioc"], WDACPOLICYNAME RMM Guard - WDAC, MACOSPOLICYNAME RMM Guard - macOS, RINGPOLICYNAME ["RMM Guard - WDAC (pilot)"], ASSIGNMENT AllDevices, EXCLUDEGROUPID the pilot group, MINIMUMRELEASEAGEDAYS 7, EXCLUDE your tool names, IDENTITY true.

The two schedules run independently: a failed pilot does not stop production. MINIMUMRELEASEAGEDAYS gives the pilot a week, so check the pilot's job history after each run.

7. Safety checks

The script refuses a file or a change instead of applying it when:

  • a WDAC deny rule would match a Windows, .NET, Office, Defender or Intune file, or an indicator would block a Microsoft or Apple sign-in, management or update domain;
  • the WDAC file is not the RMM Guard base policy, or a macOS rule would deny Microsoft-signed apps;
  • more than 25 percent of the deployed rules or indicators would change (override with -Force);
  • the policy with that name is not an RMM Guard policy: your other policies are never overwritten;
  • a device could get both the pilot and the production WDAC policy.

A refusal or failure makes the run exit with an error, so the pipeline turns red. Rolling back: disable the workflow, pipeline or schedule first, otherwise the next run puts the policy back. Then unassign or change the policy in Intune.

8. Troubleshooting

  • HTTP 400, unknown tool in exclude: a tool was renamed or removed. Copy the names again from the RMM page.
  • More than 25 percent: a large release or a big exclusion change. Check the numbers with -WhatIf, then run once with -Force (in a pipeline: the force option on a manual run).
  • would block …: the published file contains a rule that would break Windows, Intune or sign-in. Nothing was changed. Report it ↗.
  • Refusing to overwrite: the policy with that name is not an RMM Guard policy. Pick another name.
  • Refusing … both rings: the other ring's WDAC policy reaches devices this one targets. Exclude the pilot group from the production policy (-ExcludeGroupId) and run again.
  • Skipped, version … days old: expected with -MinimumReleaseAgeDays. The next run applies it.
  • CredentialTypeNotAllowedAsPerAppPolicy: your tenant blocks client secrets. Use the certificate or OIDC.
