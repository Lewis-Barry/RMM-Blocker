Automate

One PowerShell script keeps the WDAC policy, the macOS deny list and the Defender indicators in your tenant up to date with this site. Run it on a schedule and new tools are blocked without anyone downloading a file.

Download Sync-RMMGuard.ps1 · Download Setup-RMMGuardApp.ps1

The policies are enforced. Every run can change what your devices block. Keep a pilot group, and let production follow a week later.

1. How it works

  1. The script downloads the retrieval links with your exclusions: /api/wdac.xml, /api/macos.json and /api/iocs.csv.
  2. It checks every file against fixed safety rules (step 2) before anything is sent to your tenant.
  3. It finds your policy by name. Missing: it creates it and assigns it. Present: it compares and only writes when something changed.
  4. Defender indicators are compared one by one: new ones are imported, changed ones updated, removed ones deleted. Indicators you created yourself are never touched.
./Sync-RMMGuard.ps1 -Target Wdac,Macos,Ioc -WdacPolicyName 'RMM Guard - WDAC' -Exclude 'AnyDesk','TeamViewer' `
    -Assignment AllDevices -TenantId contoso.onmicrosoft.com -ClientId <app id> -CertificatePath ./RMMGuardSync.pfx -WhatIf

Needs PowerShell 7.4 or later. -WhatIf shows what would change without changing it. Every run ends with one line per target: created, updated, unchanged or skipped.

Exclusions are tool names exactly as the RMM page shows them. Copy them from Copy custom retrieval links on the RMM page, which shows the command with your current exclusions.

2. Safety rules

  • Structure: the WDAC file must be the RMM Guard base policy (same PolicyID, same rule options, two allow-all rules). Indicators must be Block rules titled LOLRMM - …. macOS entries need a Team ID, and Google, Adobe, 1Password and Cloudflare need a Signing ID too. A rule for Microsoft's Team ID stops the run: Company Portal, the Intune agent and Defender are Microsoft-signed.
  • Canaries: a deny rule that would match Explorer, svchost, lsass, PowerShell, Defender or the Intune agent, or an indicator for Microsoft sign-in, Intune, Windows Update or Defender, stops the run.
  • Size: when more than 25 percent of the deployed rules or indicators would be added or removed, the run stops. Review the change, then run once with -Force.
  • Ownership: the script only updates a WDAC policy that carries the RMM Guard PolicyID and a macOS policy whose description starts with RMM Guard macOS deny list. Your other policies are never overwritten.
  • Release age: with -MinimumReleaseAgeDays 7 a new version is applied only once it has been published for seven days. Exclusion changes on the version you already run apply at once to the WDAC and macOS policies; Defender indicators carry no version of their own, so indicator changes always wait for the release age.
  • Pilot ring: the pilot and production WDAC policies share one PolicyID, so a device must never get both. Assign the pilot policy to the pilot group, and the production policy to all devices with -ExcludeGroupId set to the pilot group. Pass the other ring's WDAC policy name with -RingPolicyName so the script does not mistake it for a duplicate. The templates below do this. Defender indicators are tenant-wide and are only synced by the production run.
  • Rolling back: disable the workflow, pipeline or schedule first, otherwise the next run puts the policy back. Then unassign or change the policy in Intune.
  • A failure or a stop makes the run exit with an error, so the pipeline turns red and production does not run after a failed pilot.

3. App registration

The script signs in as an app with two permissions: Microsoft Graph DeviceManagementConfiguration.ReadWrite.All and WindowsDefenderATP Ti.ReadWrite. Ti.ReadWrite only lets the app see and change the indicators it created itself. Indicators you imported earlier by hand stay in place; delete them in Defender once the sync runs.

Setup-RMMGuardApp.ps1 creates the app, grants admin consent and adds a credential. Sign in as Global Administrator, or as Cloud Application Administrator plus Privileged Role Administrator.

# Certificate (default; works in tenants that block client secrets)
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com

# OIDC for GitHub Actions: no secret and no certificate
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -CredentialType None -FederatedSubject 'repo:contoso/rmm-guard:ref:refs/heads/main'

# Remove the app, its permissions and the .pfx again
./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -Remove

The script prints the ClientId you need below. A client secret is possible with -CredentialType Secret, but many tenants block secrets and they expire; prefer OIDC or a certificate.

4. GitHub Actions

  1. Create a private repository. Add Sync-RMMGuard.ps1 to its root and github-workflow.yml as .github/workflows/rmm-guard-sync.yml.
  2. Run Setup-RMMGuardApp.ps1 with -CredentialType None -FederatedSubject 'repo:<owner>/<repo>:ref:refs/heads/main'.
  3. In the repository, Settings → Secrets and variables → Actions → Variables, add RMMGUARD_TENANT_ID, RMMGUARD_CLIENT_ID and RMMGUARD_PILOT_GROUP_ID (the object ID of your pilot device group). These are not secrets: OIDC needs none.
  4. Put your exclusions in EXCLUDE at the top of the workflow.
  5. Actions → RMM Guard sync → Run workflow. Check both jobs, then the policies in Intune. After that it runs every Monday.

Certificate instead of OIDC: the end of the workflow file shows the two secrets and the lines to change.

5. Azure DevOps

  1. Add Sync-RMMGuard.ps1 and azure-pipelines.yml to the root of an Azure Repos repository.
  2. Run Setup-RMMGuardApp.ps1 -CredentialType None and note the ClientId.
  3. Project settings → Service connections → New → Azure Resource Manager → Workload identity federation (manual). Name it rmm-guard, enter the tenant, the ClientId and any subscription the app can read (the task requires one; give the app the Reader role on it). Copy the Issuer and Subject identifier it shows.
  4. In Entra, open the app → Certificates & secrets → Federated credentials → Add → Other issuer, and paste both values. Then finish the service connection.
  5. Pipelines → Library → variable group rmm-guard with RMMGUARD_PILOT_GROUP_ID and EXCLUDE.
  6. Create the pipeline from the YAML file and run it once by hand.

6. Azure Automation

  1. In your Automation account, Identity → System assigned → On. Copy the Object (principal) ID.
  2. Grant the permissions to it: ./Setup-RMMGuardApp.ps1 -TenantId contoso.onmicrosoft.com -ManagedIdentityObjectId <object id>.
  3. Runtime Environments: use PowerShell 7.4 and add the module Microsoft.Graph.Authentication from the gallery.
  4. Runbooks → Create, type PowerShell, runtime 7.4. Paste the contents of Sync-RMMGuard.ps1 and Publish.
  5. Add two weekly Schedules with parameters. Pilot: TARGET ["Wdac","Macos"], the pilot policy names, ASSIGNMENT your pilot group ID, IDENTITY true. Production: ["Wdac","Macos","Ioc"], the production names, ASSIGNMENT AllDevices, EXCLUDEGROUPID the pilot group, MINIMUMRELEASEAGEDAYS 7, IDENTITY true.

7. Run it yourself

With your own Intune admin account. Defender indicators need the app, so this covers WDAC and macOS:

./Sync-RMMGuard.ps1 -Target Wdac,Macos -WdacPolicyName 'RMM Guard - WDAC' -Interactive -WhatIf

Already deployed the policies by hand from this site? Pass their names: the macOS export is called Block RMM tools (macOS), and for WDAC use the name you gave it. The script recognises them and updates them in place. If it finds the RMM Guard WDAC policy under another name, it stops and tells you which name to pass.

8. Troubleshooting

  • HTTP 400, unknown tool in exclude: a tool was renamed or removed. Copy the names again from the RMM page.
  • More than 25 percent: a large release or a big exclusion change. Run with -WhatIf, check the numbers, then once with -Force.
  • would block …: the published file contains a rule that would break Windows or Intune. Nothing was changed. Report it ↗.
  • Refusing to overwrite: the policy with that name is not an RMM Guard policy. Pick another name.
  • Skipped, version … days old: expected with -MinimumReleaseAgeDays. The next run applies it.
  • CredentialTypeNotAllowedAsPerAppPolicy: your tenant blocks client secrets. Use the certificate or OIDC.
