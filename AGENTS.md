# Agent instructions

- Don't run `run-tests.mjs` or `tests.html` for simple front-end changes like copy, markup or styles. Run them only when asked, or when logic changes in `app.js`, `policy.js`, `ioc.js`, `kql.js`, `build.mjs` or `products.json`.
- Whenever adding, changing, or removing IOCs, regenerate the Defender CSVs with `node build.mjs`, verify the generated network discovery KQL includes the updated indicators, and commit all affected outputs. The KQL is built from the bundled IOC CSVs in `kql.js`; update its generation or tests if needed to keep every current IOC represented.
- `macos.js` (used by `app.js` for the **macOS** platform, on by default next to Windows) builds the macOS deny list from the `macos` blocks in `products.json`, as an Intune JSON body and as a PowerShell script that embeds it. Every rule needs a `teamId`; Team IDs that also sign everyday software (Microsoft, Google, Adobe, 1Password, Cloudflare) need a `signingId` too. `validateMacos` in `macos.js` is the single validator and `node build.mjs --check` runs it. Only add a rule after reading the signature from the vendor's real installer with `codesign -dvvv`, and record the installer URL in `source`.
- `scripts/sync-macos.mjs` (macOS only) adds and re-verifies Team ID rules from Homebrew installers; its pure parts are tested in `scripts/sync-macos.test.mjs`. A product rejected for macOS goes in `scripts/macos-ignore.json`. Run `node --test scripts/` after changing any script.
- Before every commit, regenerate `llms.txt` with `node build.mjs` (it is built from the template in `build.mjs` and `products.json`; edit the template if site facts, pages or copy changed) and set the **Last updated** chip in `index.html` to today's date, in the form `Nov 8, 2026`.
- `tool-pages.mjs` (called by `build.mjs`) generates one static page per tool in `tools/`, the `tools/index.html` list and `sitemap.xml`, all from `products.json`. Never edit those files by hand: change the template in `tool-pages.mjs` and run `node build.mjs`, which also deletes the page of a removed tool. Commit the regenerated `tools/` folder with any `products.json` change; `node build.mjs --check` fails if a page is missing or stale.
- `automation/Sync-RMMGuard.ps1` syncs the retrieval links into a tenant. Its guards mirror the site: `$script:BroadTeamIds` must equal `broadTeamIds` in `macos.js`, `$script:PolicyId` and `$script:RuleOptions` must match `Blocking_RMMsv5.xml`, and `$script:IocHeader` must match `iocHeaders` in `ioc.js`. Run `pwsh -c "Invoke-Pester ./automation"` after changing any of those or the script; the tests use the repo's own policy, CSVs and products.json as positive controls. Keep `Invoke-Sync` as the script's last line; the tests load everything above it.
- A new rule that a canary in `Sync-RMMGuard.ps1` rejects (for example a deny path matching `explorer.exe`) will stop every customer's sync. Fix the rule, not the canary.
- The same goes for a deny rule in a protected folder (anything `Microsoft*`, `System32`, `WindowsApps`, …), a new `.dll` rule, and an indicator under a Microsoft or Apple domain. The few published exceptions are pinned in `$script:WdacFolderAllowed`, `$script:WdacDllAllowed` and `$script:IocFirstPartyAllowed`; add to them only after checking the rule cannot hit Windows, Intune, Defender or sign-in.
