# Agent instructions

- Don't run `run-tests.mjs` or `tests.html` for simple front-end changes like copy, markup or styles. Run them only when asked, or when logic changes in `app.js`, `policy.js`, `ioc.js`, `kql.js`, `build.mjs` or `products.json`.
- Whenever adding, changing, or removing IOCs, regenerate the Defender CSVs with `node build.mjs`, verify the generated network discovery KQL includes the updated indicators, and commit all affected outputs. The KQL is built from the bundled IOC CSVs in `kql.js`; update its generation or tests if needed to keep every current IOC represented.
- `macos.js` (used by `app.js` for the **macOS** platform, on by default next to Windows) builds the macOS deny list from the `macos` blocks in `products.json`. Every rule needs a `teamId`; Team IDs that also sign everyday software (Microsoft, Google, Adobe, 1Password, Cloudflare) need a `signingId` too. `validateMacos` in `macos.js` is the single validator and `node build.mjs --check` runs it. Only add a rule after reading the signature from the vendor's real installer with `codesign -dvvv`, and record the installer URL in `source`.
- `scripts/sync-macos.mjs` (macOS only) adds and re-verifies Team ID rules from Homebrew installers; its pure parts are tested in `scripts/sync-macos.test.mjs`. A product rejected for macOS goes in `scripts/macos-ignore.json`. Run `node --test scripts/` after changing any script.
